# Beginner 트랙 커리큘럼

## 과정 목표

12강을 마치면 로컬 쿠버네티스 클러스터에 애플리케이션을 배포하고, 네트워크·설정·저장소·상태 확인·업데이트·문제 해결의 기본 흐름을 스스로 수행할 수 있습니다.

## 권장 진행 방식

- 주 1~2강, 강의당 90~120분
- 개념 20%, 실습 70%, 회고 10%
- 매 강의 시작 전 이전 강의의 리소스를 정리했는지 확인
- 명령을 복사하는 데 그치지 않고 `get`, `describe`, `logs`로 결과를 설명

## 단계별 구성

| 단계 | 강의 | 핵심 주제 | 완료 결과 |
|---|---:|---|---|
| 시작 | 0강 | Docker Desktop, kubectl, kind 설치와 클러스터 생성 | 로컬 단일 노드 클러스터 준비 |
| 시작 | 1강 | Pod, 매니페스트, apply/get/describe/logs/delete | nginx Pod 실행과 관찰 |
| 워크로드 | 2강 | ReplicaSet, Deployment, 선언적 상태, 자가 복구 | Pod 삭제 후 자동 복구 확인 |
| 워크로드 | 3강 | 롤링 업데이트와 롤백 | 무중단 이미지 업데이트와 복원 |
| 네트워크 | 4강 | Service, ClusterIP, DNS | 클러스터 내부 통신 확인 |
| 네트워크 | 5강 | Ingress와 로컬 라우팅 | 호스트 이름 기반 접근 |
| 설정 | 6강 | ConfigMap, Secret, 환경 변수와 볼륨 | 이미지 재빌드 없이 설정 변경 |
| 안정성 | 7강 | requests/limits, liveness/readiness/startup probe | 비정상 컨테이너 감지와 트래픽 차단 |
| 데이터 | 8강 | Volume, PV, PVC, StorageClass | Pod 재생성 후 데이터 유지 |
| 운영 | 9강 | Namespace, ServiceAccount, RBAC | 최소 권한 읽기 계정 구성 |
| 운영 | 10강 | Events, logs, exec, 디버깅 시나리오 | Pending/CrashLoopBackOff 원인 해결 |
| 패키징 | 11강 | Helm chart 구조, values, upgrade | 재사용 가능한 애플리케이션 패키지 |
| 종합 | 12강 | 웹 앱 배포 종합 실습 | 배포·노출·설정·상태 확인·롤백 시연 |

## 단계별 체크포인트

### 1단계: 시작 (0~1강)

- 클러스터와 컨테이너의 관계를 설명할 수 있다.
- 명령형 작업과 YAML 기반 선언형 작업의 차이를 설명할 수 있다.
- Pod의 상태, 이벤트, 로그를 확인할 수 있다.

### 2단계: 워크로드와 네트워크 (2~5강)

- Deployment가 원하는 복제본 수를 유지하는 과정을 관찰할 수 있다.
- Service가 교체되는 Pod에 안정적인 접근점을 제공하는 이유를 설명할 수 있다.
- 잘못된 배포를 이전 버전으로 되돌릴 수 있다.

### 3단계: 설정, 안정성, 데이터 (6~8강)

- 설정과 민감 정보를 컨테이너 이미지에서 분리할 수 있다.
- 자원 요청/제한과 probe를 사용해 안정성을 높일 수 있다.
- PVC를 사용해 워크로드 수명과 데이터 수명을 분리할 수 있다.

### 4단계: 운영과 종합 (9~12강)

- Namespace와 RBAC로 범위와 권한을 제한할 수 있다.
- 이벤트와 로그를 근거로 대표적인 장애를 진단할 수 있다.
- Helm으로 동일 애플리케이션의 환경별 설정을 관리할 수 있다.

## 평가 기준

각 강의는 다음 네 항목을 모두 만족하면 완료입니다.

1. 제공된 리소스를 직접 생성하고 정상 상태를 확인했다.
2. 핵심 오브젝트의 YAML에서 `metadata`와 `spec`의 역할을 설명했다.
3. 관찰 명령의 출력으로 결과를 증명했다.
4. 실습 리소스를 정리하고 클러스터 상태를 다시 확인했다.
